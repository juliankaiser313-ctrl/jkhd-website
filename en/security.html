// Security

There are no client files here.

We sell nothing and work for no one, so no outside documents and no outside systems sit with us. What has to be secured is something else: that no program and no slip of the hand moves money nobody meant to move. That nothing can be quietly altered after the fact. And the little the partner access does store — that is further down.

// Interlocks

Seven locks that do not open in passing.

Not one of them is a matter of trust. Most are rules in the code, one is a possibility that does not exist at all — and the reason sits next to each, usually because that very thing went wrong once.

01

The kill switch shuts the door, not the window

Once it is pulled, no new entries come about; open trades run out rather than being thrown onto the market. It opens again only when a person acknowledges it with a note — and that state survives every restart.

02

Nothing goes beyond the machine's own setting

An intervention on the control panel can make the machine more careful; it cannot make it bolder than its own setting — a value that would do so is quietly pulled back and does not appear as an intervention at all. What a person has tightened themselves they may also take back: that is the way home to the setting, not past it.

03

Unable to read means not acting

What the system cannot read unambiguously does not count as permission: if the operator's instruction stays unclear, trading starts with entries closed. Because "I cannot currently check whether a kill switch is pulled" is no reason to enter anyway. Not knowing means not acting.

04

"Real money" is a finding, not a claim

There is no file with which live operation could be asserted — a flag that can be set regardless of the actual connection would have been set on the day it was needed. Instead it is checked: stand-ins, test doubles, copy templates and sources that merely replay a recording are recognised and refused. Every error along the way is a lock, not a shrug.

05

There is no path for manual trades

Nobody can place an order by hand into the systematic accounts — we cannot either. Otherwise machine and hand results could no longer be told apart, and a system whose numbers cannot be separated can no longer be tested.

06

The change is a sequence, not a switch

First close entries, then prove nothing is open, then end the running process, then witness the standstill — and only after that start the target state. Any ambiguity halts the change right there and says why: a broken file is not "nothing open", two journals that disagree are not "probably zero". On top of that come a waiting period and questions that have to be answered first — against our own overconfidence, not against strangers.

07

Two limits above everything, and none may be missing

Before every new trade, the sum of all open stop risks is held against an upper limit — five accounts in the same direction are one trade at five times the size, not a portfolio. Alongside it runs a loss brake across everything that adds the realised loss of the day to the unrealised loss of open positions. An account's daily budget hangs on the balance at the start of the day: a profit in the morning does not make it bigger. If one of these limits is missing, nothing starts — there are no silent defaults here.

// Records

What happened cannot be quietly altered.

A log you can smooth out afterwards is not a log. So the entries hang together.

01

Chained journals

Every entry carries a checksum over its predecessor. Change a line later and you break the chain.

  • Writing only appends, it never overwrites
  • The check runs at start-up, not only when somebody asks
  • A run meant to produce evidence stops at a broken chain before it writes a single line
  • A merely displaying component keeps running but reports the break visibly — switching it off would heal nothing
  • The check covers all the chains, not only the convenient ones
  • A data set admits only one writer at a time: the lock is held by the operating system, not by an agreement — and it is released by itself when the process dies
  • Within one program it is tested that two simultaneous writers lose no entry and leave the chain intact
02

Every intervention leaves a line

The log line comes after the change on purpose: a log without the change would be a lie, a change without its log line is a visible arrear — and it gets filed.

  • Writing happens only with the version the editor saw when opening
  • Two changes at once: the second is rejected rather than overwriting
  • If the instruction cannot be written to disk, it does not apply — and says so instead of failing quietly
  • The failed attempt and the click that changed nothing are logged as well
  • A secret appears in no log — neither entered correctly nor incorrectly
  • Files are replaced whole or not at all, never half
  • A hard-killed process leaves half a line: it is first secured as evidence and only then taken out of the journal — and the check names it, even though it is not a broken chain
03

Testing cannot touch operation

The separation between test run and running system is enforced, not agreed upon — because an agreement failed to hold once.

  • A test run writes into throwaway directories slipped underneath it
  • A guard then looks at what has newly appeared in the real data
  • It checks the property "points at operation", not a list of known names
  • The few files operation may create itself are listed individually, each with its reason

// Data

What is stored here at all.

The shortest answer to any data question is to hold very little.

01

This website

Static pages, nothing more.

  • No cookies, no trackers, no counting pixels
  • All that stays on the device is the choice of light or dark — and only once the switch is used
  • No content from other servers — fonts and images live here
  • No contact form on the text pages: whoever writes, writes an e-mail
  • What the web server logs is stated in the privacy notice
02

The partner access

What a partner has given us stays as long as they are a partner. Everything the sign-in itself produces expires by itself.

  • On the contact page there are two fields: the address for the code — that one goes to the access — and a questionnaire that only fills your own mail program
  • A code is stored only as a checksum with a random addition, never in clear text, and is valid briefly and exactly once
  • An open sign-in ends with the browser tab, expires by itself anyway, and signing out ends it immediately; here only a checksum of it is kept
  • The access is reachable only encrypted — an unencrypted call is redirected, and the browser is told not to try it any other way in future
  • Partner data does not sit in the area the web server delivers, and is barred by rule on top of that — two locks, checked
  • Repeated requests are throttled
  • Unknown addresses get the same empty answer as partners: the access does not reveal who belongs
03

No payment data

There is nothing to buy, so there is nothing to pay either.

  • No card, account or invoice data from anyone
  • No basket, no billing system, no payment provider
  • What we pay brokers and providers ourselves is our own business and sits in no online system of this site

// Honestly

What we cannot show you.

This list is here because a security page without it gives only half the answer.

No certification

We are not certified to ISO 27001 and hold no comparable seal. The source code is not open: what is written here is an account, not a proof.

No external audit

No third party has examined these procedures. We test ourselves and have every finding of our own challenged by a second pass — better than nothing, but not an outside verdict.

No cover around the clock

No security team, no shift sitting at a screen around the clock. Automatic watchdogs keep an eye on the programs and raise an alarm — that reaches somebody, but it does not replace standby duty.

No redundancy

No second system, no failover. An outage ends operation instead of continuing it elsewhere. That the books survive a restart is tested — it does not replace a data centre.

No lock has ever held real money

There is no counterparty attached through which real money could move. The readiness check therefore always says no — not because that is written in, but because the connection is missing. None of the locks above has ever seen a real case with real money.
