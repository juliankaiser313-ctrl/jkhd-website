// Testing

How we test, before anything runs.

Testing is not a step at the end here, it is the largest part of the work. This page says what is proven for a single module, what a complete system adds — and what you hold in your hands in writing at the end.

// Principles

Four rules fixed before the first run.

Whoever decides afterwards what counts as a pass is not testing — they are looking for a justification.

Separate data

The search runs on one period, the confirmation on another that stays untouched until then. How often a confirmation period has already been used is counted — it wears out.

Abort criteria fixed in advance

The threshold a candidate has to hold is fixed before the first run and is not lowered afterwards. A test repeated until it fits is not a test.

Costs are part of the test

Fees, the bid-ask spread and execution deviation belong in the calculation, not in the footnote. An idea that only works without costs does not work.

Every run repeatable

Seed, data vintage, parameters and software version are recorded with every result. A number that cannot be produced again does not count as a result here.

// A single module

If only one stage is delivered, exactly that stage is proven.

Every module leaves the house with its own test file. You get the evidence for what you are buying — and the statement of the assumptions under which it holds.

Module 01

Data & connectivity

Tested against the raw data itself, never against a second derivative of it.

  • Bar aggregation recomputed against the tick total
  • Artificial gaps injected — are they flagged instead of filled?
  • Connection loss forced, resumption checked
  • Contract rolls and clock changes traced in the stored data
  • Raw data unchanged after the run
Module 02

Research & signal discovery

What is tested is not the best result but the search that led to it.

  • Complete parameter map, dead cells included
  • Same seed, same data vintage, same result
  • Search and confirmation periods demonstrably separate
  • Comparison against doing nothing as a baseline
  • Number of trials fully logged
Module 03

Statistical hardening tests

We test this stage with cases whose answer we already know.

  • Pure noise as input — the suite must reject
  • An artificially planted signal — the suite must find it
  • Multiple-testing correction against the real number of trials
  • Reality Check and out-of-sample on the same data
  • Rejected candidates documented, not deleted
Module 04

Risk & capital

Limits are not taken on trust. In the test they are triggered on purpose.

  • Daily loss limit deliberately breached
  • Trailing drawdown carried across an equity high
  • Mark-to-market breaker fired mid-position
  • State after the stop checked: position, protection, log
  • Position size recomputed against the remaining buffer
Module 05

Execution & orders

Tested against real market access in the test environment, not against an assumption.

  • Partial fills forced and processed onward
  • Restart mid-position — no second order
  • Bracket at signal time held against the actual fill
  • Delayed and rejected broker responses played through
  • Order log complete and immutable
Module 06

Operation & monitoring

What is tested is the failure, not normal operation. That works anyway.

  • Process killed hard — does self-healing take over?
  • Feed silenced: the silent failure has to be noticed
  • Alerting path played through to the recipient
  • Shadow tracking held against the actual figures
  • Restart performed from the manual, by someone else
What a module test does not cover: a module can work perfectly on its own and still fail in combination — at an interface, a time zone, a rounding. That is why every test file states the assumptions under which it was measured, and which guarantees the surrounding software in your house has to keep for the evidence to hold.

// A complete system

Six stages before a system is switched on.

Every stage is allowed to abort. An abort is not a setback but the point of the exercise — the earlier, the cheaper.

01

Component testing

Every stage is proven on its own, exactly as described above. Only once a component stands by itself is it connected.

02

Interaction

The chain from data through signal and the risk layer to the order is played through as a whole. This is where the faults show up that no single stage makes: a time offset between two components, a double trigger, a rounding at the limit.

03

Full run on history

The complete chain runs over periods left untouched during the search — with fees, spread and execution deviation. The result is documented with every rejection, not only with the good stretches.

04

Shadow operation

The system runs alongside live, computes and reports — but does not trade. Computed and actual behaviour are held against each other; the deviation goes into the fidelity report. This stage does not end by calendar but when the deviation is explainable.

05

Trial operation with a small stake

Real orders, a small stake, every limit live. Two months are provided for this — after which you may decline. Whatever comes up in that time is fixed, and the stage concerned is proven again.

06

Acceptance and handover

Test report, reproduction instructions, logs, source code and operating manual pass to you — in full. We keep no copy, no parameter and no derivative of it.

// Stress tests

What we break on purpose.

A system shows its character not in normal operation but on the day something fails. So we bring that day about beforehand — and record what has to come out of it.

Feed loss mid-session

The data connection drops while a position is open.

Expected trading pauses, gap flagged, nothing caught up

Restart with an open position

The machine restarts while a position and its protection are in the market.

Expected position recognised, no second order

Broker answers too late

The confirmation of an order fails to arrive or arrives delayed.

Expected order counts as unconfirmed, no blind resend

Overnight price gap

The market opens far away from the last price, beyond the protection.

Expected breaker fires, loss stays within bounds

Contract roll and clock change

The traded contract rolls, and the clock jumps by an hour.

Expected no price jump, no duplicate bar

Retroactive data correction

The vendor corrects prices that have long since been processed.

Expected new vintage versioned, old one still traceable

// The outcome

What you hold in your hands at the end.

A test you are merely told about is not one. You receive it as documentation — verifiable by your own people.

01

Test report

What was measured, with what, and with what result.

For every test: data vintage, period, assumptions, metrics and the verdict. Including the runs that did not pass — those are in the same document, not in a second one.

  • metrics
  • assumptions
  • rejections
02

Reproduction instructions

So your house can recompute every figure itself.

Seed, data vintage, parameter set, software version and the command that produced the run. Whoever recomputes it on your side must get the same number — otherwise it was not a measurement.

  • seed
  • data vintage
  • software version
03

Acceptance record

The basis for your internal sign-off.

Every stage with date, result and the person responsible, plus the open points and the operating manual for the serious case. Your audit function gets something to hold, not trust.

  • stages
  • open points
  • emergency operation

// Honestly

Where a test ends.

It proves behaviour

A passed test says how the system behaves under known conditions. It says nothing about the return next quarter — and whoever claims otherwise is selling something other than software.

It is not finished

After switch-on the testing continues as monitoring: shadow tracking and drift detection measure the same quantities, only daily. If a signal loses its effect, it is retired.

It only knows the past

Testing runs against data that already exists and against failures we can imagine. An event that has never occurred in that form is not in the test — only the limits meant to catch it are.

It does not replace your judgement

We disclose what we measured and how. The decision whether that is enough for your house stays with you — which is why we give you the documents to make it.
